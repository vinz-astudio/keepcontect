# Keep Contact — 核心业务优先级与当前已知 Bug 清单

> 本文件是专门为云端 Claude 准备的「第二档」参考资料，浓缩了人类在日常决策（Decisions）、已知问题（Known Issues）及真实生产运行中沉淀的硬性判断。

## 一、最不能出错的 3 个核心场景（优先级基准）

### 场景 1（最高优先级 · 生命底线）：真实失联必达（真人倒下无活动，必须通知到人）
- **定义**：用户在清醒期内长时间没有任何设备活动（分类为 `miss_kind = 'silent'`），超过静默阈值且未自证，漏斗必须稳定、无静默阻断地逐级升级（`self` ➔ `group` ➔ `community` ➔ `terminal`），最终解锁地址与紧急联系人并通知到真实监护人。
- **底线要求**：系统绝不能因为后台采集器假死、定时任务漏跑、或代码异常抛错而发生“该报警时完全静默”。

### 场景 2（核心体验与信任基石）：技术故障不惊扰（手机拔电/关机/无网，不能吓到家人）
- **定义**：设备的掉电、关机、无网络或系统限制（分类为 `miss_kind = 'device_unreachable'`），是**设备不可达**而非**人身失联**（ADR-0040 修订一「`device_off` 不得判为人身失联」）。
- **底线要求**：
  - 通知文案必须如实说明「KC 与设备失去联系，可能已关机或没电」，绝不能直接写成「人身突发危险」。
  - 阶段升级**最多升到 `group` 或 `community` 协助确认，严禁升级到 `terminal` 终态，严禁解锁家庭地址与联系人要求上门探视或协助报警**（2026-11-02 人类已确立方案 A）。

### 场景 3（防打扰与社会资本保护）：恢复活动即解除（本人恢复活动立即撤销告警，杜绝误报死锁）
- **定义**：一旦检测到受监护人产生了服务端验证合格的本人新活动（`behavior_pings` ingest_version=2），系统必须自动解除普通活跃告警（ADR-0045）。
- **底线要求**：
  - 消除历史残留死循环：绝不强制用户必须在 PWA/Native 端画手势 pattern 才能解警（除非有效监护人明确开启了特殊守护要求）。
  - 杜绝“用户已经在发消息，家里人还在收到失联轰炸”的严重社会资本损耗。

## 二、当前已知 Bug 清单（按平台、频次、严重度）

1. **【后端 / 全平台 · 严重度 P1 · 本次修复目标】设备不可达（`device_unreachable`）告警一路升至 terminal 并解锁资料**
   - **现象**：当手机因拔电断网被判定为不可达时，超时后仍从 community 升入 terminal，向紧急联系人推送“紧急：已解锁地址，请上门探视或报警”。
   - **频次**：近 30 天内发生了 6 次（涉及 iOS tester、Chunwei 等账号）。
   - **影响**：严重违背 ADR-0040，制造虚假紧急恐慌。

2. **【iOS 原生 · 严重度 P1 · 待后续架构探索】iPhone 拔电且锁屏时，APNs 静默推送唤醒率极低甚至为 0**
   - **现象**：手机一旦拔掉充电线，在锁屏状态下几乎不响应服务器发出的 15 分钟/30 分钟静默推送（24h 敲门实验 90 次拔电敲门 0 次响应，一插电立即响应）。
   - **频次**：高频必然发生（只要 iPhone 长时间拔电锁屏）。
   - **影响**：拔电的 iPhone 极易被误分类为 `device_unreachable`，导致被动心跳中断。

3. **【后端数据库 · 严重度 P1 · 已打临时补丁】Supabase Free Nano 实例资源吃紧与 pg_cron 历史膨胀导致卡死**
   - **现象**：生产 Nano 仅 0.5G 内存，`cron.job_run_details` 历史积累至 78 万行且无清理，导致 `scheduled_job_health` 超时卡死数据库 45 分钟。
   - **频次**：历史发生 1 次（2026-10-30）。
   - **当前状态**：已部署 `20261030051627` 限制扫描 7 天窗口并每日自动清理，但 Nano 磁盘 I/O 额度仍处于低位（约 17%）。

4. **【移动端 / 应用商店合规 · 严重度 P2 · 本地工作区已有改动待发版】权限显著披露与隐私政策需与实际收集完全一致**
   - **现象**：Google Play / App Store 审核对 Android 使用情况访问权限（UsageStats）和身体活动权限（Motion）的显著披露（Prominent Disclosure）有严格文案与时机要求。
   - **频次**：提审与政策核查时触发。
   - **状态**：本地工作区修改了 `PrivacyPolicy.tsx`、`guardianPermissions.ts`、`native.ts`，待伴随下一版本原生打包一并发布。

5. **【iOS 早期捷径用户 · 严重度 P2 · 待客户端设备重新配置】部分早期用户的独立快捷指令（Shortcut）自动化静默中断**
   - **现象**：早期依赖旧 GET `/ping` 或旧版自动化 URL 的用户（如 Sanagu），因系统清理或未切换到新版 App Opened 凭据，过去数周无有效 ping。
   - **频次**：个别历史测试账号。
   - **影响**：该部分账号被动心跳停滞，需在手机端重新配置绑定新 URL。
