# Prompt for the local AI: Android + Desktop 0.7.12 release

Copy everything below the line to the local AI on the Windows machine.

---

你在 Keep Contact 仓库（Windows，本机有 Android SDK、keystore、Tauri 签名私钥 keepcontact.key）。
任务：发布 Android 和桌面版 0.7.12。iOS 已由云端 CI 构建，不用管。不要改任何代码；遇到失败就停下，
把完整错误写进报告，不要自己修代码或跳过检查。

1. 同步代码
   - `git status --short`：有未提交改动就先 `git stash push -m "pre-0.7.12"`，并在报告里列出文件名。
   - `git checkout main && git pull --ff-only origin main`
   - 确认 HEAD 包含提交 `0ee1c1e`（chore(release): 0.7.12 on every surface）。
   - `npm ci`
   - `npm run typecheck`、`npm test`：必须全过（约 784 个测试）。
   - 版本核对：`src/lib/version.ts`、`src-tauri/tauri.conf.json`、`android/app/build.gradle` 的 versionName
     都应该是 0.7.12。

2. Android
   - `npm run release:android -- 0.7.12`（会把 versionCode +1、构建并签名 APK、写生产库 app_versions、
     发 GitHub Release v0.7.12）。
   - 按上次 0.7.11 的流程提交并推送脚本产生的改动（release-artifacts、build.gradle、version.ts、
     public/version.json），提交信息 `chore(android): release v0.7.12`。
   - 记录：APK 文件名、大小、SHA-256、versionCode、GitHub Release 链接。

3. 桌面版（Tauri，Windows x64）
   - 设置环境变量 `TAURI_SIGNING_PRIVATE_KEY`（keepcontact.key 的内容）和密码（如果有），然后
     `npm run tauri build`。
   - 产物改名为 `KeepContact-0.7.12-Setup.exe` 和 `KeepContact-0.7.12-x64.msi`，放进
     `release-artifacts/desktop/`，同时覆盖 `KeepContact-Setup.exe` / `KeepContact.msi` 镜像（和 0.7.11 一样）。
   - 上传这两个文件到 GitHub Release v0.7.12（与 APK 同一个 Release）。
   - 提交并推送，提交信息 `chore(desktop): release 0.7.12 installers`。
   - 记录：两个文件的大小、SHA-256、下载链接。

4. 桌面版冒烟测试（在这台电脑上）
   - 覆盖安装 0.7.12，确认 app.exe 属性版本为 0.7.12，程序能启动并登录。
   - 首页"动态与风险通知"标题右边应有"自检工具 ▾"按钮；点开后点"发送测试通知"，几秒内 Windows 右下角
     应弹出 Keep Contact 通知。
   - 把 Keep Contact 窗口最小化，再点那条通知：窗口应该回到最前面。记录是否成功。
   - 点开"自检工具"后点"试按「一切安好」"：按住 1 秒松手应提示"请按住 3 秒"；按满 3 秒应提示"按住 3 秒有效"。
   - 把窗口最小化，再点右下角托盘图标：窗口应该恢复并回到最前面。
   - 不要点"测试解锁通知"（会给圈子成员发"告警已解除"通知）。
   - 重要：冒烟测试要在你自己能看到的桌面上启动 app。如果你的命令行没有图形桌面，安装后不要启动 app，
     在报告里写"未启动，需人工测试"——上次在看不见的桌面里启动，导致人类必须重启电脑才能打开窗口。

5. 报告
   - 写 `15_Release_0.7.12_Android_Desktop_Report_20261103.md`，上传到 Google Drive 文件夹 KC_Claude_Handoff
     （和之前的报告放在一起）。内容：每步的命令、退出码、关键输出；第 2、3 步的产物信息；第 4 步每项的结果
     （成功 / 失败 / 未测，以及看到的现象）。
