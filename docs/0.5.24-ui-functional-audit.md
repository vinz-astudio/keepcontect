# Keep Contact 0.5.24 · Prototype 功能对照审计

日期：2026-08-02  
范围：当前 `APP_VERSION = 0.5.24` 的 React 功能源码、现有项目真相记录，以及 `Prototype/interactive_prototype.html`。

## 证据边界

这不是截图视觉验收。Product Design Audit 要求先捕获并检查截图，但当前用户选中的 in-app Browser 只暴露 `file://` prototype，现有浏览器策略不允许我控制或重新捕获该页面；因此下面的结论是“源代码/运行记录对照”，不是像素级视觉结论。Prototype 自身的静态测试仍为 10/10；`Prototype/design-qa.md` 也明确记录了视觉验收 blocked。

## 分步健康度

1. **Onboarding：部分健康，功能语义仍不对齐。** Prototype 已把用户任务压缩成价值说明 → 自动识别本机设置 → Ready/Limited；生产 `OnboardingWizard` 仍按平台分支展示多步技术设置。尤其 `onboardingPlatform === 'ios'` 会显示 Shortcut/PWA 指引，但项目运行证据把 iOS native 作为 `ios-passive-v1`；native 与 iOS PWA 需要拆成两个真实分支。
2. **Watch/Home：视觉清楚，安全语义不够。** Prototype 的三层状态（人员告警、This device、Evidence）方向正确，但 “No active alerts / Everything looks safe and sound” 仍可能把“当前没有告警”误读成“所有人安全”。实际 `StatusBoard` 还要表达成员覆盖、最后活动、Concern CTA、加载/空/错误状态。
3. **Me：信息架构正确，功能覆盖不足。** Prototype 正确分开偏好与设备事实，但没有等价呈现生产 Me/Profile 的扫码同步登录、推送被拒修复、Pattern 的 uid 隔离生命周期、退出/删除账户，以及 EmergencyInfoCard 的真实加密/解锁约束。漂亮的静态状态不能当成这些功能已实现。
4. **Circles/邀请：视觉可用，关键交接未完成。** 实际 Circles/Guardians 支持成员状态、责任方向、分享活动开关、Guardian/Ward、任务和 QR/扫码；现有 QR 任务证据显示 Android/iOS/web 跨表面 deep-link handoff 尚未闭合，且 QR 文案称“会过期”而 code 实际 durable。应列为下一步强化，不应继续占用 0.5.24 发布阻塞。
5. **SOS：状态设计好，交互契约不一致。** Prototype 宣称长按 2 秒；生产 `TabBar` 的 `HOLD_MS` 是 1400ms。Prototype 还模拟了“Min acknowledged”，不能推导真实服务端已接收、通知已投递或离线失败。必须统一时长，并把“服务端收到 / 通知投递 / 对方确认 / 失败重试”分别表达。
6. **Routine/Pattern：位置正确，完成条件要真实。** 把 Safety check-in Pattern 放进 Me 是对的；生产实际是旧手势验证、uid-scoped hash、保存/清除和练习流程，Prototype 的轻量 dialog 不能暗示它已经等价实现。
7. **跨平台回退：当前是高风险。** `OnboardingWizard` 只监听 `focus`/`pageshow` 更新权限，没有 Capacitor `appStateChange`；从 Android 系统设置返回时可能仍显示 Pending，而 Me 已是 Granted。Prototype 的即时 Allow/Ready 视觉隐藏了这个真实回退问题。
8. **验证：当前是高风险。** 生产 `listRecentPings()` 只要找到过去五分钟任意 ping 就通过，没有本次测试的 baseline、startedAt、source 或 nonce；用户可能没做当前动作却看到验证通过。Prototype 已提出“新信号 baseline”，但还不是生产行为。

## “美观但功能不足”的具体差距

| 优先级 | Prototype 表面 | 实际不足 | 应怎么改 |
|---|---|---|---|
| P0 | iOS native / iOS PWA 的清晰 onboarding 分流 | 生产 iOS enum 与 native runtime 语义混用，Shortcut 文案会误导 native 用户 | 生产数据模型拆 `ios_native`、`ios_pwa`；按真实能力渲染；PWA 的限制单独说清 |
| P0 | “Check this phone”→Ready/Limited | 生产接受任意 5 分钟内旧 ping | 每次测试建立 baseline，要求测试开始后的匹配来源新信号；过期、无来源、失败都给下一步 |
| P1 | Me 的 This device 状态卡 | 回系统设置后状态可能不刷新；完成后也没有持久、可修复的 readiness 入口 | 原生 resume 重新查询权限；Me/Home 持久显示 `Ready/Limited/Needs action`，提供 Fix now / Finish later |
| P1 | 安静的 Watch 成功页 | “No active alerts” 不等于安全；缺证据时必须是 Unknown/Limited | 标题写“当前没有活动告警”；旁边显示最近可信证据、覆盖质量和未知原因 |
| P1 | 简洁的 Me | 隐藏扫码同步、推送修复、账户删除、Guardian/Ward/task、加密 EmergencyInfo 约束 | 保持卡片风格，但补真实入口；未实现的动作不要做成成功态 |
| P1 | 2 秒 SOS + 对方确认 | 实际 1.4 秒；确认/投递/离线未分层 | 统一 1.4 秒或先改运行时；增加 server received、delivery、ack、retry 状态 |
| P1 | Invite / Add member 对话框 | QR deep-link 跨 Android WebView、iOS Home Screen、浏览器不闭环；过期文案与持久 code 冲突 | 修复 verified HTTPS App/Universal Links、跨表面 pending handoff、真实 TTL；QR 文案改成真实生命周期 |
| P2 | 技术设置被隐藏、文案更友好 | 生产仍暴露 Usage Access、Motion、Test Ping、100% Guarded 等内部术语/绝对承诺 | 保留“为什么需要”解释；把技术名放二级帮助；禁止 100% 隐私承诺 |
| P2 | 静态 calm/happy path | 生产有 loading、empty、auth retry、offline、push denied、成员隐藏、分享关闭等状态 | 每个核心卡补 loading/empty/error/offline/denied；状态颜色和动作保持 P1–P8 语义 |
| P2 | Emergency location reveal | Prototype 地址是 mock；生产实际由 pattern/encryption 和 crisis 授权控制 | 标注 demo 数据；只在真实授权 SOS 状态展示，说明谁能看、何时结束、如何撤销 |

## 下一步强化顺序

1. **Onboarding 真实性**：拆 iOS native/PWA；修复 resume 刷新；将 ping 验证改为本次运行 baseline。
2. **持久 readiness**：把 Ready/Limited/Needs action 变成真实状态模型，贯穿 Onboarding、Home、Me。
3. **危险路径一致性**：统一 SOS 长按时长和投递状态，禁止模拟确认覆盖真实失败态。
4. **邀请交接**：完成 QR deep-link、pending invite handoff 和真实 TTL 文案；这是仍未完成且显著的功能候选，不是 0.5.24 发布阻塞。
5. **Prototype parity**：按真实功能补 Me/Circles 的入口和错误态；所有 mock 交互标明 demo，不把视觉完成当作 runtime 完成。
