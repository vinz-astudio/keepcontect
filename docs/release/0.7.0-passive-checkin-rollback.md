# 0.7.0 passive check-in rollback

This is a forward-only safety rollback. Do not edit or remove an applied
migration, rewrite completed windows, delete evidence, change causal snapshots,
silently substitute the legacy threshold, or auto-resolve an open alert.

## Immediate containment

With authorized production service-role access, enable the global switch and
record a specific incident reason:

```sql
select private.set_passive_checkin_global_kill_switch(
  true,
  'INCIDENT-ID: concise reason and UTC timestamp'
);
```

Then verify:

```sql
select globally_disabled, reason, updated_at
from private.passive_checkin_runtime_control
where singleton;

select engine_mode, kill_switch_active, count(*)
from public.passive_checkin_accounts
group by 1, 2 order by 1, 2;
```

The switch stops new passive inactivity alerts, blocks new live activation and
marks shadow/live accounts Limited. It does not switch anyone to `legacy`,
erase finalized state, or close an existing alert. Existing alerts keep their
original explicit-resolution lifecycle.

## Stabilize

1. Stop further client/public/Store rollout and new account activation.
2. Preserve the aggregate report interval, incident counters, causal window
   IDs and affected artifact hashes. Do not export raw personal payloads.
3. Confirm there is no dual-engine alert and no passive automatic resolution.
4. Fix schema/function defects with a new forward migration. Fix clients with
   a higher build/version; never replace already-published bytes under an
   existing versioned filename.
5. If a download manifest is already public, change it only after the chosen
   replacement artifact is reachable and `app_versions` agrees. Do not point
   `0.7.0` at old or unsigned desktop binaries.

Returning a migrated account to `legacy`, disabling the switch, deleting
records, or resuming rollout each needs a separate human decision. When that
decision exists, disable the switch explicitly and verify the same two queries:

```sql
select private.set_passive_checkin_global_kill_switch(false, null);
```

Before resuming, rerun the full shadow report and every previously failed
device/review gate. A green local test suite alone is not sufficient evidence
to resume production authority.
