# Keep Contact 0.5.24 Prototype Function-Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved warm prototype into a directly testable UX contract that preserves production Watch, Circles, Me, Routine, onboarding, and SOS functionality through progressive disclosure.

**Architecture:** Keep the existing single-file HTML/CSS/JavaScript prototype. Add a labelled prototype scenario toolbar outside the phone frame, a small scenario data model in the inline script, and semantic DOM renderers for Watch states; keep lower-frequency Circles and Me functions as real interactive prototype controls and dialogs. The dependency-free Node test parses the real HTML, validates the state model and script syntax, and enforces observable destination/state contracts before each implementation batch.

**Tech Stack:** HTML5, CSS custom properties, vanilla JavaScript, Node.js built-in `assert`/`fs`, Material Symbols Rounded.

## Global Constraints

- Preserve the current warm frosted-glass, DM Sans/Nunito visual system, four primary destinations, and centered SOS.
- Watch order is Action summary → People I watch → Check-in Tasks → Activity History.
- Every collapsed person row exposes relationship/Circle, state, evidence age/source, coverage quality, and an applicable action.
- No-alert, Ready, Live, delivery, expiry, or acknowledgement claims require matching scenario/runtime evidence.
- Onboarding auto-detects the current surface and contains two user tasks plus a result; platform/scenario controls stay outside the phone frame.
- Prototype simulations are visibly labelled Demo.
- Do not change production React, native, backend, database, migration, or release files.
- All edits use UTF-8 and preserve existing user/other-AI visual work outside the approved functional scope.
